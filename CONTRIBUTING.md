# Contributing to this kit

This is a personal baseline, so changes should reduce future decision-making rather than introduce options for their own sake.

1. Make one purposeful change.
2. Update the relevant document, checklist, or ADR.
3. Verify the template builds and tests on the target SDK.
4. Prefer a small recipe over placing every optional dependency in the starter.

When a project needs a deliberate exception, record why in `adr/` instead of silently changing the default.
